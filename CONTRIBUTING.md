# Contributing to Tapo Studio

Thanks for helping! The easiest ways to contribute:

1. **Tell us whether it works with your light.** Open a [compatibility report](https://github.com/Bambob01/tapo-studio/issues/new?template=device_report.yml). This is the most valuable thing for a project with limited hardware access.
2. **Report a bug** with the [bug template](https://github.com/Bambob01/tapo-studio/issues/new?template=bug_report.yml). Remove your Tapo email, password and (if you like) IP addresses first.
3. **Send a pull request.** Small, focused changes are easiest to review.

## Set up

```bash
git clone https://github.com/Bambob01/tapo-studio
cd tapo-studio
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -e ".[dev,all]"

python -m tapo_studio --mock         # runs with pretend lights, no hardware needed
python -m pytest                     # the test suite
```

To exercise the real-lights code path in a browser without any hardware, run `python tests/e2e_fake_server.py`. It runs the app (not in demo mode) against the strict fake of the `tapo` library.

In `--mock` mode the app fakes three lights (two L930 strips and an L530 bulb) and the music mode has a built-in demo track, so you can work on almost everything without hardware.

## How it's put together

```
tapo_studio/
  __main__.py   command line, creates the private key, starts the server
  server.py     web server + security middleware + API routes (all input validated here)
  core.py       the app's brain: devices, actions, scenes, schedules, capability checks
  devices.py    which Tapo models exist and what each can do   <- start here to add a model
  driver.py     TapoBackend (real lights via the `tapo` library) and MockBackend (demo)
  effects.py    effect validation, clamping, bundled studio effects, frame builder
  live.py       live modes: frame streaming, animations, screen sync, music, daylight, playlists
  audio.py      beat analysis (kick/snare/hats, tempo lock) and audio capture
  color.py      Oklab blending, palettes
  store.py      settings file, password protection (Windows DPAPI)
  data/         preset tables, generated by tools/extract_presets.py
  static/       index.html, app.js, app.css (no build step, no dependencies)
tests/          pytest suite (see below)
tools/          maintenance scripts
```

**The golden rule of the device:** each write takes about 0.3 s. `live.py`'s `Streamer` keeps exactly one request in flight per light and always sends the newest frame. Please don't add code that fires requests faster than that.

## Tests

| File | What it covers |
|---|---|
| `test_effects_color_devices.py` | Effect validation and clamping, colour maths, model families |
| `test_audio.py` | Beat, kick, snare and tempo detection on synthetic songs |
| `test_core_models.py` | Capability gating for other models, address rules, live-mode races, storage |
| `test_server_security.py` | Attack scenarios: missing token, DNS rebinding, CSRF, oversized and malformed input, XSS |
| `test_driver_tapo.py` | The real-hardware driver run against `tests/fake_tapo.py`, a strict fake of the library |
| `test_library_contract.py` | Checks our assumptions against the **real** `tapo` library (skipped if it isn't installed; CI runs it) |

When you change behaviour, add a test. The fake library in `tests/fake_tapo.py` raises `AttributeError` for anything the real library doesn't have, so keep it in step with the library's type stubs.

## Adding support for another Tapo model

Edit `tapo_studio/devices.py`:

1. Add the model to `MODELS` with its family and the name of the `ApiClient` method that returns its handler.
2. If its features differ from the existing families, add a `Family` with the right capability set. The capabilities are `power`, `brightness`, `color`, `white`, `zones`, `effects`.
3. Run the tests, then try it on the real light and open a compatibility report.

The UI hides features automatically based on capabilities, and actions skip lights that can't do them.

## Adding a new kind of light

A backend is a small class in `driver.py` with the async methods listed at the top of that file (`connect`, `power`, `color`, `lighting`, ...). `MockBackend` is the simplest example. A different brand would add its own backend, a way to choose it, and its own entries in `devices.py`.

## Regenerating the preset tables

`tapo_studio/data/*.json` come from the Rust source of the MIT-licensed `tapo` library:

```bash
git clone --depth 1 https://github.com/mihai-dinculescu/tapo
python tools/extract_presets.py ./tapo
```

Please don't copy data or code from GPL-licensed projects (such as `python-kasa`) into this repository, so that it can stay MIT-licensed.

## Security-sensitive areas

Changes to `server.py`, `store.py`, or the address checks in `core.py` need extra care. Read [SECURITY.md](SECURITY.md), keep every `/api` route behind the token check, and never render user-supplied text with `innerHTML`.

## Style

Plain, readable Python and JavaScript. No build tooling for the front end. Keep dependencies to a minimum, and justify any new one.
